# 図（Mermaid）の作り方

記事に図を入れるときの規約。図は Mermaid で書く（エディターのプレビュー表示前提。ワークフロー図の実例は [workflow.md](./workflow.md)）。

## いつ図を作るか

- 図は本文の理解を助ける補助。本文の文脈と関係ない図は作らない。見出しや段落が言っていることを図で言い直す、が基本。
- 図に起こす過程は本文の点検にも使える。図化の途中で説明の抜け（前提・層・分岐の欠落）が見えたら、図をいじる前に本文を補う。

## 膨らませない

- 図が本文から独立して膨らみ始めたら、図を直すのではなく構成のほうを見直す（別セクションを立てる、その図をやめる）。「この見出しを説明したいだけ」という原点に戻す。
- 対比・応用・派生を1枚の図に詰め込もうとしたら、それは図ではなく本文の不足のサイン。

## ラベルの語彙

- ラベルを比喩側の語にするか現実側（開発）の語にするかを最初に決める。両者が混ざると往復が増える。
- 既定の着地: 図は現実の開発の語で書き、比喩は本文が担う。
