# 執筆スタイル

書き手（ユーザー）の文体・語彙・避けたい表現をまとめた定点ドキュメント。日付の記録ではなく「今のスタイルはこう」を書く。新しい気づきは日付見出しで足すのではなく、該当テーマの記述へ統合する。文体・執筆姿勢の運用は [writing-policy.md](./writing-policy.md)、校正ツールの設定は [markdown.md](./markdown.md) を参照。

## 文体

- です・ます調、一人称は「私」、温度感はカジュアル寄り（デフォルト。詳細は [writing-policy.md](./writing-policy.md)）
- 常体の言い切りをリズムとして意図的に混ぜる。です・ます の段落でも、印象づけたい文に限って言い切りを 1 文挟む。本人言「リズムなのか、揺れなのかを意識するならリズムを重視したい。平坦な文章は読み応えがなく、記憶に残りにくい」。です・ます へ揃える校正はしない
- 文体ルールは humanizer より優先する。humanizer は英語前提で、日本語に当てると「短く言い切れ」が常体（だ・である／体言止め）を混ぜて です・ます を壊すことがある。観点は採るが、常体化したリライトは です・ます に直してから採用する

## 言語化の癖

- 概念をまず比喩で掴む。本人言「自分が概念を理解するときにまず比喩で掴んでいる」。記事の比喩は装飾ではなく思考の入口そのもの。比喩を読者にも渡したい志向がある（「人間駆動 vs コンピューター駆動の設計物」「細胞の新陳代謝」「プレイヤー↔ディレクター」はいずれも本人発）
- タイトルを並列形式で構造化したがる（『A と B、C』のような連結）。複数の概念が地続きであることをタイトルの構造で表す
- 記事を書く前に、頭の中にふわっとした仮タイトル・仮方向を持っていることが多い。AI 案を見てズレを感じ、もとの像に寄せる動き方をする
- 構造案（H2 など）を見ると潜在的な違和感が言語化される。抽象的に「こうしたい」と言うより、具体物に「これは違う」と反応して軸が固まる
- AI 案の事実誤認に反射的に反応する。レトリックの好みではなく「事実として正しくない」を軸に書き換える。言語化そのものを重視し、「なぜこちらが良いか」を言葉に落とすことを大切にする

## 好む表現

- 「ふわっと考えていた」
- 「ノイズになる」（不要な情報を却下するときの本人語）
- 「視差を広げる」（視点ではなく視差。複数視点の差分を強調する語感。記事を書く動機としても機能する）
- 「越境」（開発チームの枠を越えて課題に手を伸ばす。「視差を広げる」と通底する行動語）
- 「新陳代謝」（組織・生物・ソフトウェアが変化し続けて生き延びる、という比喩）

## 避けたい言い回し

- ネガティブワードを入口に使う（例「業績が悪い」）。気づきが目的でも、ポジティブな入口を選ぶ
- 書き手の属性を主役化したタイトル・副題。根拠補強としての自己開示は良いが、読み手の学び・活用を前に置く
- 身近な対象（特定の同僚像）を実例に引く。実例化すると「対象を悪く言っている」読まれ方になるため、構造の話として書く
- 本文中の太字（`**強調**`）の多用。本人言「hoge のような強調文字は AI っぽく見られてしまう」。地の文の言葉選びと語順で強調を効かせる（`docs/session-logs/` 等の内部メモの太字は構造化目的なので対象外）
- 本文にダッシュ（`──` / em dash）を使う。本人言「日本語のブログ記事でダッシュを使うことがないから」。区切り・言い換え・余韻は句読点と語順で表現する
- ideas のブレストメモを飾る（太字・`>` 引用ブロック・`──`）。他記事と同じプレーン箇条書きで統一する
- 自リポジトリ・執筆環境の内情を記事の実例に出す。本人言「リポジトリの話はしてほしくない」。効果で語る形にする
- ウィキリンク記法 `[[...]]`。素の Markdown で非リンク表示になる。リンクは切れやすいので、アイデア段階までは相対 Markdown リンクで許容し、公開時に見直す

## 用語・カタカナ語の選び方

- カタカナ専門語は「普段のブログ記事で自分が使うワードか」で取捨選択する。口にしないカタカナは日本語に寄せる（例: カップリング → 結合）。一方インターフェース／リファクタリング／モジュールは普段使うので残す。英語の対応語を残したいときは初出で一度だけ括弧書きする（例「密結合（カップリング）」）

## 機械校正（textlint）への姿勢

- プリセットの推奨形にこちらが寄せる。ルールは曲げない。本人言「textlint のプラグイン自体が技術記事向けの校正なので、推奨の形でブログ記事を書きたかったから」。`allow` で逃げず、本文を言い換えて通す
- 唯一の例外は `ja-no-weak-phrase`（「思います」等）を off にすること。文体と衝突するルールだけ外す（厳格ルールより文体デフォルトを優先）
- `allow` は固有名詞でフルネームしか書けない語だけの例外にする。言い換えや半角スペースで回避できるものは本文側で対処する
- 本人の言葉でも、最終的には校正する。ブレストメモの verbatim もアイデア段階で引っかかったら見直す。本人言「本人の言葉といえど、最終的には校正するべき」
