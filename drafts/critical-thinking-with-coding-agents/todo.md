## 本人が後で追加したい項目

- [x] シンプルには2種類ある、という判断力の話を足すか（2026-07-12 本人発、同日反映。H2「『良いもの』は、たいていシンプル」に統合と分離の対比＋インプットと相似探しの2段落を追加）

- [x] 言語化の観点を足す（2026-07-12 反映。新 H2「問い直しは、言語化を加速させる」）
  - 批判的思考やデザインで何より求められるのは言語化。「こっちのほうが良いのではないか」には常に何かしらの理由があり、それを言葉に落とし込むことが求められる
  - エージェントに批判的に返す行為そのものが言語化。問い直しを言葉にできないと、エージェントにも伝わらない
- [x] 批判的思考は、デザインやドメインモデルを考えることと似ている、という角度を足す（2026-07-12 反映。新 H2「『良いもの』は、たいていシンプル」第1段落）
- [x] 「良いものはシンプル」という観点を足す（2026-07-12 反映。同 H2。乾電池の比喩も本人発で追加）
  - エージェントは生成物のボリュームが多く、シンプルな実装から遠のきやすい。良いものは基本的にシンプルなケースが多い。良いデザインは1つで2つのことを解決したりする
  - 良いものは捨てやすく、独立的であり、他と干渉しないことが多い（2026-07-12 本人追加）
  - エラーハンドリングなど重要な処理ももちろん含まれるが、それらも再利用できる形にして KISS の原則を目指す。もしくは生成物をレビューすることが何よりも大事
  - 本人の経験則（長年プログラミングをしてきた一次体験）: 実装はしなければしないほど良い。運用コストが増えず、解決できるなら実装しないことのほうが有意義。断定の根拠としてそのまま使える
