# roi-thinking-for-engineers レビュー記録

## 2026-09-26

- 実施日: 2026-09-26
- 今回の観点: 一般的な客観チェック

良かった点は次のとおり。

- 事業生産性を自分で定義せず、登壇レポートの ROIC と3観点に根拠を置いている。費用対効果と投資対効果を並べ、人件費も費用に含めると補っている
- 外部リンク3件（DORA、AWS DynamoDB、Findy Tools）は記事の要約どおりだった
- ボトルネックの3事例が「声 → 対応 → 実測値」の型でそろい、節の主張と一致している
- DynamoDB の段落が、通説に AWS 公式の推奨と自社の実測の2つで反論している
- 「シンプル＝部品が少ないことではない」と定義し、部品の増える webhook の構成に先回りして答えている
- 「効果が見えてくるのはこれから」「数字に表れにくい価値もある」と限界を正直に書いている

指摘と対応は次のとおり。

| ------ | ---------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |

| P0     | ボトルネック3事例                        | 効果が秒数だけで、お金の軸につながらない                                         | 反映。GitHub Actions の無料枠超過の課金を減らす狙いを追記（金額は出せない）                    |
| P0     | マイクロサービスの見直し                 | 「釣り合わない額」に中身がない                                                   | 反映。「通常の利用の範囲でも赤字になる値段」に変更                                             |

補足。

- 22件中、反映 18件（1件は一部 todo へ）、見送り 3件、todo へ 2件（oxfmt の手元の数字、webhook の本番後の数字）
- webhook の移行はまだ本番前で、レビューの質問で初めてそれと分かった。事例の時制が完了済みで書かれていないかは、次回も確かめるとよい
- レビュー中に本人の依頼で、レバレッジの引用の後の「〜からです」という理由の後置き文を削った（文体面）
- 機能の複雑さと売上増加への貢献は、次の記事のネタとして todo.md に残した
