# 単体テストの考え方/使い方 / Vladimir Khorikov（須田智之 訳）

- 概要: 単体テストを数を増やすことではなく、持続可能なプロジェクト成長への投資と捉え直す本。良いテストを退行からの保護・リファクタリングへの耐性・速いフィードバック・保守のしやすさの 4 本柱で評価する。テスト対象との結合度を下げる設計（古典学派とロンドン学派、モック乱用やテストの脆さといったアンチパターン）を扱う。サンプルは C# だが言語非依存。
- 使いどころ: AI が書くテストの質を語る軸。Claude Code などが生成するテストを 4 本柱で評価する記事の論拠にしたい。
