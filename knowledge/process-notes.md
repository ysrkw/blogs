# process-notes

ワークフロー（ideate → outline → draft → polish）を通して効いた進め方、詰まったパターンを蓄積する。

## 効いた進め方

- **H2 構造案を提示すると、それまで言葉にならなかった軸の違和感が表面化する**。抽象的に「方向性合っていますか？」と聞くより、具体的な構造を見せたほうが本人の潜在的な方向性が言語化される（2026-05-26 organization-as-software：H2 4 本案を見て「体験談中心ではなく思考フレーム中心にしたい」と転換）
- **セッション中に概念整理が言語化された瞬間、記事の射程が拡張されることがある**。整理が固まる前に出てこなかった応用・接続が、整理直後に湧く（2026-05-26 critical-thinking-with-coding-agents：論理／批判をループ構造として整理した直後に「このループはエージェントのエンジニアリングにも応用できる」が outline 終盤で出てきた。ideate のときには無かった）

## 詰まったパターン

- **書き手が頭の中で持っていた仮タイトル／仮方向を AI が聞き出していないと、タイトル案の往復が増える**。本人提案で着地するパターンになる（2026-05-26：3 案 → 改稿 3 案 → 副題なし 3 案 → 本人提案 で着地）
- **仮タイトルがあっても探索の往復には価値がある**（2026-05-26 critical-thinking-with-coding-agents：本人発言「もっと早く着地したかったが、会話することで思い出したこともあったので、そこまで無駄ではなかった」）。ヒアリングして仮タイトルを起点にしつつも、探索をゼロにはしない設計が望ましい

## 段階の往復

- 2026-05-26 organization-as-software：outline 中盤で「体験談中心 → 思考フレーム提示中心」に軸を切り直した。ideate には戻らず outline 内で再定義して進めた

## ワークフロー設計の方針（meta）

- 各段階は**書き手代替を避ける**温度感で統一されている（質問→本人判断→反映の往復）
- スキル自己改善も同じ温度感。AI は提案をログ化するだけで SKILL.md は直接書き換えない
- ファイル名に日付を付けるのは `articles/` と `knowledge/sessions/` のみ。途中段階は日付なし
