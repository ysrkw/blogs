# book-log

読んだ本をナレッジに蓄積する補助スキル。ブログ執筆ワークフロー（ideate → outline → draft → polish）の外にある。
記事の参考文献や根拠として後から再利用できるよう、本ごとに `knowledge/books/{slug}.md` を作り、索引 `knowledge/books.md` に1行追加する。

## 位置づけ

- ユーザーが「本を読んだ」と報告したときに発動する
- 1冊につき1ファイル。詳細は `books/{slug}.md`、`books.md` はリンク索引と運用ルールだけを持つ
- 既存の本の構造・記録項目は `knowledge/books.md` の運用ルールが正

## 記録項目

`books/{slug}.md` に置く項目は次の6つ。

1. 概要（要確認） … 本の中身。AI の知識ベースで下書きし「（要確認）」を付ける
2. 使いどころ … その本をどのテーマ・文脈で記事に使いたいかという本人の意図メモ
3. 書誌（参考文献用） … 著者・訳者・書名・原題・出版社・刊行年・ISBN・一次情報リンク
4. 体裁（任意） … ページ数・判型など
5. 記事で引いた対応 … 本のどの概念を記事のどこに対応づけたか
6. 登場記事 … この本を引いた記事のスラッグと役割（核／参考文献など）

## 進め方

1. 本の特定
   - ユーザーの書名から、著者・訳者・版を確認する。曖昧なら1往復で確かめる

2. 書誌の取得（ここがスキルの核）
   - WebSearch で書誌を探し、WebFetch で一次情報を裏取りする
   - 一次情報の優先順は 出版社ページ → CiNii → 版元ドットコム → 書店ページ
   - 取る値は 著者・訳者・書名・原題（原著年）・出版社・刊行年月・ISBN
   - ISBN は ISBN-13 とカッコで ISBN-10 を併記する
   - AI の記憶で埋めず、必ず取得した一次情報で確定する

3. 概要の下書き
   - 概要を2〜4文で書き、先頭に「（要確認）」を付ける
   - 事実誤認がありうる前提で、本人の補正を待つ

4. 使いどころのヒアリング
   - 「どのテーマ・文脈で記事に使いたいか」を本人の言葉で聞く
   - 刺さった章・キーアイデア、乗りたいのか反論したいのかの温度感も拾う
   - 本人の発言はそのまま転記する。AI 風の言い換えをしない
   - まだ使う当てがなくても、思いつきメモとして残してよい

5. 保存
   - スラッグは原題か書名の `kebab-case`（例 `team-topologies`）。ユーザーに確認する
   - 末尾「テンプレート」をベースに `knowledge/books/{slug}.md` を作る
   - `knowledge/books.md` の「一覧」に1行追加する（書式は末尾「索引の行」）

## textlint に通す書き方

このリポジトリは Markdown 編集時に textlint が走る（PostToolUse hook）。次を守ると差し戻されにくい。

- 1文は100字以内。長くなったら句点で分ける
- 数えられる数は算用数字（「1つ」「9つ」「2021 年」）
- リスト項目を `**語**:` の形（太字＋コロン）で始めない。機械的と判定される
- 指摘が出たら丸ごと `--fix` せず、1つずつ本人判断で直す
- 漢字 6 連続で指摘される固有名詞（書名・出版社名・人名など）は、原則そのまま残す。`.textlintrc.json` の `max-kanji-continuous-len.allow` にその語を追加して素のまま通す（例: `知識創造企業`、`東洋経済新報社`）。書名や固有名詞を変えたくないというライターの方針が優先
- `！` や `？` を含む正式書名も、書名を変えずにそのまま残す。`no-exclamation-question-mark.allow` に書名の全文字列を追加すれば、その範囲内の記号は無視される。例は `ドメイン駆動設計入門 ボトムアップでわかる！ドメイン駆動設計の基本`
- インラインコード（`` `…` ``）で囲む回避は、許可リストに載せるまでもない一過性の語に限った最終手段とする。コードスパン内は ja-technical-writing が検査しない。鉤括弧「」では回避できない

## テンプレート

`knowledge/books/{slug}.md` の雛形。これをベースに埋める。

```markdown
# {書名} / {著者}（{訳者} 訳）

- 概要（要確認）: {2〜4文。本の中身}
- 使いどころ: {本人の言葉。どのテーマ・文脈で記事に使いたいか}
- 書誌（参考文献用）:
  - 著者: {原名（カナ）}
  - 訳: {訳者}
  - 書名: {日本語書名}
  - 原題: {原題}（原著 {YYYY} 年）
  - 出版: {出版社}、{YYYY} 年 {M} 月
  - ISBN: {ISBN-13}（{ISBN-10}）
  - 一次情報: [{出版社など}]({URL})
- 記事で引いた対応: （未使用）
- 登場記事: （なし）
```

## 索引の行

`knowledge/books.md` の「一覧」に足す1行の書式。

```markdown
- [{短縮タイトル}](books/{slug}.md) — {1行サマリ}。{使いどころメモあり・記事未使用／登場: {slug}（役割）}
```

## 重要原則

- 書誌は推測しない。一次情報で裏取りしてから書く
- 概要と使いどころを混同しない。概要は本の中身、使いどころは本人の意図
- 本人の言葉を尊重し、AI 風に言い換えない
- 記録だけして終わらない。記事で使ったら「記事で引いた対応」「登場記事」を後から更新する
