# blog-outline

ブログ執筆ワークフローの 第2段階。
`works/{slug}/idea.md` を入力に、記事の骨組み（タイトル・リード方向・見出し構造）を作る。

## 入力

- 引数: `{slug}`（省略時は `works/` 配下で `idea.md` はあるが `outline.md` が無いものを一覧表示してユーザーに選ばせる）
- 読み込み: `works/{slug}/idea.md`

## 進め方

1. コンセプトの再確認
   - `works/{slug}/idea.md` を読み、一文コンセプト・読者像・独自角度を要約してユーザーに提示
   - 「この理解で合っていますか？」と確認。ズレていれば ideate に戻ることを提案

### 1.5 仮タイトル・仮方向のヒアリング

- 「すでに頭の中にふわっとした仮タイトルや書きたい角度があれば教えてください。なければ次のステップで AI 案を出します」と一言確認する
- 仮タイトル／仮方向ありの場合：それを起点にしてバリエーション 2〜3 案を提示。**仮タイトルがあっても探索はゼロにしない**（本人発言「会話することで思い出したこともあったので、そこまで無駄ではなかった」）
- なしの場合：従来通り次のステップで 3 案提示
- 背景: organization-as-software の outline でタイトル案の往復が増えた（本人が事前に仮タイトルを持っていたが AI が聞いていなかった）

2. タイトル案 3 つ
   - 異なる角度の 3 案を提示（例: 体験談寄り／ハウツー寄り／問題提起寄り）
   - 釣りタイトルや AI 臭の強い言い回しは避ける
   - ユーザーに選ばせる、もしくはハイブリッド案を一緒に練る
   - ここで確定したタイトルは、draft 段階で本文冒頭の H1（`# {title}`）になる（`docs/templates.md`）

3. リード文の方向性
   - 本文は書かない。「最初の3〜4文で何を伝えるか」を箇条書きで合意
   - 読者が「これは自分の話だ」と思える掴みを優先

4. H2/H3 構造
   - 3〜5 個の H2 を提案。各 H2 に「要点」「含める要素」「使う一次体験」のメモを付ける
   - 1記事に詰め込みすぎない。書ききれない論点は「ボツ案・脇道メモ」へ退避
   - 順序は読者の問いの自然な流れになるよう確認

5. 保存
   - 本スキル末尾「テンプレート」のコードブロックをベースに埋める
   - 出力先: `works/{slug}/outline.md`（`idea.md` と同じディレクトリ、日付なし）
   - frontmatter の `status: outline` に更新

## 重要原則

- 構造の押し付けをしない。ユーザーが書きたい順序を尊重
- 「網羅性」より「一本の通った道筋」を優先
- ボツ案を消さない。後で別記事の種になる
- セクション数で迷ったら少ない方を選ぶ

## テンプレート

`works/{slug}/outline.md` の雛形。これをベースに埋める。frontmatter のフィールド定義は docs/templates.md を正規とする。

```markdown
---
title:
slug:
status: outline
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

## タイトル候補

2.
3.

## 構成

- 含める要素:
- 一次体験・具体例:

### H2:
```
